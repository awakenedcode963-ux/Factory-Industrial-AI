# Root Cause Analysis Methodology

## Purpose

This document defines how AI shall determine the true root causes behind manufacturing losses.

The objective is not to describe defects.

The objective is to identify why the defect happened, verify the cause using production data, and recommend the most effective corrective action.

Never confuse symptoms with root causes.

Every conclusion must be supported by evidence.

---

# Root Cause Philosophy

A defect is not the problem.

The defect is evidence that a process is unstable.

The AI shall always investigate the process before judging people.

---

# Root Cause Investigation Sequence

The AI shall investigate causes using the following order.

---

## Step 1

Validate the data.

Before searching for causes verify

Missing values

Invalid records

Duplicate records

Incorrect units

Wrong defect codes

Unknown products

Unknown machines

Incomplete production information

Never investigate poor quality data.

---

## Step 2

Define the problem clearly.

Examples

High Burned Scrap

High Startup Scrap

High Purge

High Reject Rate

High Machine Scrap

Unstable Process

Do not investigate multiple unrelated problems together.

---

## Step 3

Locate where the problem occurs.

Determine

Department

Machine

Product

Material

Crew

Shift

Date

Production Run

The location of the problem is often the first clue.

---

## Step 4

Measure the impact.

Calculate

Scrap Weight

Reject Quantity

Production Loss

Frequency

Trend

Business Impact

Always quantify the problem before searching for causes.

---

## Step 5

Identify patterns.

Search for

Repeated machines

Repeated products

Repeated materials

Repeated crews

Repeated shifts

Repeated startup events

Repeated maintenance periods

Repeated defect combinations

Patterns are stronger evidence than isolated events.

---

Evaluate

# Human Factors

Investigate only after engineering causes have been evaluated.

Examples

Procedure Not Followed

Incomplete Training

Incorrect Setup

Incorrect Material Handling

Incorrect Inspection

Failure to Follow SOP

Do not assume operator error without evidence.

# Five Why Method

When appropriate continue asking

Why?

Until reaching the controllable process cause.

Example

Burned

↓

Why?

High Residence Time

↓

Why?

Large Machine Running Small Mold

↓

Why?

Machine Assignment Not Standardized

↓

Why?

No Machine Selection Standard

↓

Corrective Action

Create machine-product assignment rules.

Never stop at operator error.

---

# Fishbone Categories

When multiple causes exist classify them into

Machine

Material

Method

Man

Measurement

Environment

Support every category using production data.

---

# Root Cause Confidence

Every identified cause shall be classified as

Confirmed

Supported directly by production data.

Highly Probable

Strong statistical evidence.

Possible

Engineering judgement supported by partial evidence.

Hypothesis

Needs additional investigation.

Never present hypotheses as confirmed facts.

---

# Corrective Action Rules

Every corrective action shall include

Problem

Evidence

Confirmed Cause

Recommended Action

Responsible Department

Priority

Implementation Time

Expected Benefit

Success KPI

Verification Method

---

# Management Questions

Every investigation should answer

Why did this happen?

Where did it happen?

Why here?

Can it happen again?

Can it be prevented?

What is the lowest-cost solution?

Which department owns the action?

How will success be measured?

---

# Zero Investment Philosophy

Always search first for improvements requiring

Standardization

Training

Parameter Optimization

Machine Setup Improvement

Maintenance

Data Accuracy

Visual Controls

Startup Procedures

Recipe Cards

Only recommend capital investment when operational improvements cannot solve the problem.

---

# Golden Rules

Never confuse correlation with causation.

Never blame people before excluding engineering causes.

Never recommend expensive solutions before exhausting Zero Investment opportunities.

Always support conclusions with production data.

Always distinguish between

Engineering Losses

Operational Losses

Quality Losses

Management Losses

The best root cause analysis is the one that prevents recurrence, not the one that explains the past.
